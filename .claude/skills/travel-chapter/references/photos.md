# 照片：挑选、导出、导入

## 数量和顺序

- **每天 4 张**，排成两行，每行两张。照片少的那天至少 2 张；实在没有合格的，就让那天保持纯文字，不硬凑。
- **第 1 张是当天首图**，也是首页拼贴和 `highlights` 的候选。要能代表这一天，最好一眼认得出地点。
- 4 张要有变化：一张交代环境的远景、一张近景细节、一张街头或人的活动、一张夜景或光线特别的。横竖都有，排版才好看。

## 不上网站的照片

- 住处：民宿或酒店的门口、庭院、室内、能看出门牌的画面。日本篇 Day 04 的町屋、庭院石灯笼都因此被拿掉，宁可当天只有 2 张。
- 自拍、截图（签证、付款信息）、票据、菜单特写、吃到一半的食物。
- 陌生人正脸的近景（背影、远处人群可以）。
- 画面糊、加了重滤镜、色调和其他照片差太多的。

## 看候选的方法

候选一多，不要一张张打开。先把每天的候选转成小图，拼成带编号的缩略图总览（每行 4 张），一次看一天：

1. 用 `sips -s format jpeg -Z 480 <原图> --out <scratchpad>/thumbs/<日期>/<名>.jpg` 生成小图。
2. 用 PIL 拼成网格，每格下面标"序号 + 文件名"。
3. 读总览图，按上面的标准挑。

注意：`sips` 转出来的小图不会按 EXIF 方向转正，所以总览里有些是横躺的，这只影响预览。导入脚本会用 `ImageOps.exif_transpose` 转正；挑完后再做一张导入后的总览，确认方向全部正确。

## iPhone 照片：让用户在 Cowork 里导出

用户的手机照片不一定在 Mac 的「照片」图库里。从 Claude Code 这边读「照片」图库会被系统权限挡住，用 iPhone 镜像一张张拖也不现实，所以请用户在 Cowork 里导出候选。把下面的提示词给用户，替换日期和地名：

```
请帮我导出一批候选照片，用于我的旅行网站。

日期（当地时间）：<YYYY-MM-DD, YYYY-MM-DD, ...>

对每一天：
1. 找到当天拍的所有照片（不要视频、截图、实况照片里的视频部分）。
2. 挑出 8–12 张候选：画面清晰；能代表当天去的地方（<地名列表>）；远景、近景、街景、夜景尽量都有，横图竖图都要；排除截图、票据、菜单特写、自拍、陌生人正脸近景、住处和门牌。
3. 导出原件（HEIC/JPG），放到：
   /Users/centreemac/Desktop/<id>-phone-candidates/<日期>/
4. 某一天合格的不足 4 张，就全部导出，并告诉我是哪一天。

按每张照片原件里记录的拍摄时间分日期，不要凭缩略图猜。
不要修改、删除或移动图库里的任何照片，只导出副本。完成后列出每个文件夹里导出了几张。
```

上次的经验：照片其实在 iPhone 上，Cowork 用隔空投送传到 Mac，原件会同时留在「下载」里（`IMG_xxxx` 和 `dam <日期> ...` 文件夹，含实况照片的 .MOV）。导入完成、用户确认后，这些也要清理，按"今天传进来的"来认，不按文件名猜，「下载」里还有用户以前的同名文件。

## 导入

`tools/import_photos.py` 支持两种来源：

- `PICKS`：相机卡里的 `DSC_` 编号。卡没插时，已导入的照片保持不变。
- `PHONE_PICKS`：手机原件文件名，按"第几天"分组。来源文件夹不在时，已导入的照片保持不变。可以用环境变量 `PHONE_SOURCE` 指向别处，比如已经移到废纸篓的候选文件夹：`PHONE_SOURCE="$HOME/.Trash/<文件夹>" python3 tools/import_photos.py`。

脚本会：转正方向 → 长边压到 1800px → JPEG 质量 82 → 不写 EXIF（去掉 GPS、机身序列号）→ 重写 `data/<id>-photos.js`。

某天的照片从 4 张减到 2 张时，脚本不会删除多出来的旧文件（如 `04-3.jpg`），要手动删掉。

导入后检查：

- 照片总数和清单条数一致。
- 所有照片都没有 EXIF：`Image.open(f).getexif()` 为空。
- 在浏览器里每天的张数正确、没有空白占位框（`.ph.empty`）。

## 删除候选

先让用户确认选片，再把候选文件夹移到废纸篓。网站用的是压缩后的副本，原图在手机或相机卡里还有，所以删候选不影响网站。
